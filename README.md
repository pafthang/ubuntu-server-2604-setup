# Ubuntu server 2604 setup

Первичная настройка чистого Ubuntu Server (24.04+, включая будущую 26.04)
одной командой или тремя шагами:

- базовые пакеты и инструменты диагностики;
- оболочка **fish** (автоподсказки из коробки) + fzf, zellij, micro, helix;
- доступ по SSH **стролько по ключам**, firewall **UFW**, защита от брутфорса
  **fail2ban**, автообновления security, персистентный журнал, опциональный swap.

Все скрипты **идемпотентны**: обрыв связи посреди прогона лечится повторным
запуском — продолжится с того же места без дублей.

---

## Быстрый старт

### Вариант A — одной командой (рекомендуется)

Безопаснее — скачать, посмотреть и запустить:

```bash
curl -fsSL https://raw.githubusercontent.com/<YOU>/infra-bootstrap/main/bootstrap.sh \
  -o bootstrap.sh && sudo bash bootstrap.sh all \
  --key-url https://github.com/<YOU>.keys --port 22
```

Компактнее, но канал не проверяете:

```bash
curl -fsSL https://raw.githubusercontent.com/<YOU>/infra-bootstrap/main/bootstrap.sh \
  | sudo bash -s -- all --key-url https://github.com/<YOU>.keys
```

> ⚠️ Для воспроизводимости подставьте в URL хэш коммита вместо `main`:
> `.../<YOU>/infra-bootstrap/<commit-sha>/bootstrap.sh`.
> Тогда состояние сервера никогда не зависит от будущих правок ветки.

#### Что произойдёт

1. **Этап 10** — обновление системы, установка пакетов, fish/micro/helix/zellij/fzf,
   micro как редактор по умолчанию (`sudoedit`, `git commit`, `crontab -e`),
   fish становится login-shell (вступит в силу со следующего логина).
2. **Этап 20** — загрузка публичных ключей из `KEY_URL`, проверка формата,
   дедупликация, запись в `/root/.ssh/authorized_keys`.
3. **✋ Гейт доступа** — скрипт останавливается и ждёт (по умолчанию до 15 минут),
   пока вы откроете **второй терминал** и войдёте: `ssh root@<ip>`.
   Вход детектируется автоматически по системному журналу (`Accepted publickey`)
   — это доказательство извне, а не вопрос «у вас получилось?».
4. После подтверждения — финальное `[y/N]`, затем **этап 30**:
   закрытие паролей, drop-in конфиг sshd, UFW, fail2ban (через systemd-journal),
   автообновления security, персистентность journald, часовой пояс, swap.

Если за таймаут входа не случилось — hardening НЕ применяется, система остаётся
доступной как есть. Догнать позже: `sudo bash bootstrap.sh harden`.

#### Флаги

| Флаг                            | Значение                                            | По умолчанию    |
| ------------------------------- | --------------------------------------------------- | --------------- |
| `all\|packages\|access\|harden` | режим: полный прогон или один этап                  | `all`           |
| `--key-url URL`                 | откуда брать публичные ключи (URL или путь к файлу) | из `config.env` |
| `--port N`                      | порт sshd после hardening                           | `22`            |
| `--timeout SEC`                 | сколько ждать повторный вход на гейте               | `900`           |
| `--yes`                         | отвечать «да» на подтверждения                      | интерактивно    |

`--yes` нужен там, где второго SSH-входа физически не бывает — например,
тестовый прогон в LXC-контейнере:
`sudo bash bootstrap.sh all --key-url ... --yes --timeout 5`.

### Вариант B — поэтапно (как раньше, если хочется контроля)

```bash
git clone https://github.com/<YOU>/infra-bootstrap.git
cd infra-bootstrap
cp config.env.example config.env    # вписать KEY_URL, при желании SSH_PORT/TIMEZONE

sudo ./10-packages.sh               # перелогиниться → окажетесь в fish
sudo ./20-ssh-access.sh             # ⚠️ см. правило ниже
# ✋ вторая сессия, проверить вход по ключу, первую не закрывать!
sudo ./30-hardening.sh              # только после успешной проверки
```

`bootstrap.sh` при запуске рядом с локальными файлами этапов использует их,
а не сеть — так что оба варианта гоняют одни и те же скрипты.

## Гейт доступа: почему так сложно

Ключи доставляются **тем же каналом, который затем закрывается** (`PasswordAuthentication no`,
firewall). Ошибка в порядке операций = самозапирание. Поэтому единственное место,
где автоматизация честно останавливается — момент между «ключи положили» и
«пароли выключили». Подтверждение берётся не у пользователя (он может ошибаться),
а у независимого источника — журнала sshd.

Полностью убрать человека можно только доставкой ключей **до** включения машины —
через cloud-init/Terraform метаданные облака (`users: [ ssh_authorized_keys: ... ]`).
В этом случае precondition гарантирован платформой, и скрипт бежит без остановок.
Для фермы машин — правильный путь; для одного сервера гейт стоит ~60 секунд.

## Конфигурация

Приоритет источников: аргументы CLI → переменные окружения → `config.env`.

| Параметр      | Где задаётся                 | Смысловое значение               |
| ------------- | ---------------------------- | -------------------------------- |
| `SSH_PORT`    | CLI `--port` / config.env    | порт sshd после hardening        |
| `KEY_URL`     | CLI `--key-url` / config.env | источник публичных ключей        |
| `TIMEZONE`    | config.env                   | часовой пояс; пусто = не трогать |
| `CREATE_SWAP` | config.env                   | `true` → создать swapfile        |
| `SWAP_SIZE`   | config.env                   | размер swapfile                  |

GitHub отдаёт ваши публичные ключи одним запросом: `https://github.com/<user>.keys`
— удобно как единая точка правды для всех серверов.

## Если что-то пошло не по плану

Прервались где угодно — продолжайте соответствующим режимом:

```bash
sudo bash bootstrap.sh packages   # заново обновит/доустановит без вреда
sudo bash bootstrap.sh access     # доложит отсутствующие ключи
sudo bash bootstrap.sh harden     # требует непустой authorized_keys; откажется иначе
```

Частые случаи:

- **fish не стала активной** — она вступить в силу со следующего логина;
  текущая bash-сессия этому не помеха.
- **Ctrl-R/Ctrl-T в fish молчат** — установлен старый fzf (< 0.48 без `fzf --fish`);
  инструкция PPA — комментарием в конце установки пакетов в `10-packages.sh`.
- **Сменили порт и потерялись** — живое соединение не рвётся; из него:
  `ss -tlnp | grep sshd` покажет фактический порт. На локальной машине сохраните:

  ```
  Host myserver
      HostName <ip>
      User root
      Port <новый>
  ```

## Проверка после установки

| Действие                                   | Ожидание                              |
| ------------------------------------------ | ------------------------------------- |
| `ssh -p PORT root@host`                    | пускает без пароля                    |
| `ssh -o PubkeyAuthentication=no root@host` | `Permission denied (publickey)`       |
| `ufw status verbose`                       | `Status: active`, порт SSH в LIMIT    |
| `fail2ban-client status sshd`              | отвечает, счётчики нулевые            |
| набрать команду в fish                     | серая автоподсказка, `→` принимает её |
| `journalctl -b -1` после ребута            | журнал прошлой загрузки читается      |
| `hx --health`                              | таблица языков helix                  |
| `zellij`                                   | интерфейс с подсказками клавиш внизу  |
| `timedatectl`                              | выставленный часовой пояс             |

После первого прогона этапов 10 рекомендуется `reboot`: могли приехать новые ядра.

## Ограничения и осознанные упрощения

- Работаем под **root** — конфиги уже лежат в `/root`; миграция на отдельного
  пользователя с sudo возможна позже отдельно.
- Бинарные установки zellij/helix рассчитаны на **x86_64**; для arm64 поправьте
  URL релизов в функциях `install_*`.
- Бэкапы **не входят** сознательно: это отдельный проект (restic/borg + внешний
  сторадж) и по важности он стоит выше всего перечисленного здесь.
- Публикуемые Docker'ом порты обходят правила UFW — при добавлении контейнеров
  потребуется отдельная настройка.

## Идеи расширения

- **Ubuntu Pro** (бесплатно до 5 машин) → Livepatch: патчи ядра без ребутов;
- **cloud-init / Terraform** — доставка ключей вне SSH убирает гейт полностью;
- `starship` (промпт с git-статусом), `zoxide` (умный cd) — однострочные установщики;
- restic/borg → внешний сторажд.
